# Configure registration and password-recovery email

Your local Youcai administrator login does not need Firebase. Outgoing verification and password-recovery messages use **Resend**. There is currently no email-provider configuration form inside CRM User Management. The server’s provider settings are entered through Manus’s protected website-settings input, not through a CRM user profile or password field.

## One-time setup

1. Create or sign in to your own [Resend account](https://resend.com/). Your Gmail address can own that provider account and receive CRM email, but it is not a domain you can verify for arbitrary Resend sending.
2. In Resend, open **Domains → Add Domain**. Have your website provider verify a sending subdomain. For example, `notifications.youcaimedical.com` is a proposed subdomain, **not an already verified sender**. The provider must approve it and install the exact Resend-generated sending records. Resend recommends using a subdomain. [1]
3. Wait for Resend to show the sending domain as **Verified**. Use a sender address on that exact verified domain, such as `Youcai CRM <noreply@notifications.youcaimedical.com>`. This is an example only until the domain is actually verified. Do not use a Gmail address as the sender for this adapter or substitute the provider’s restricted test sender for real onboarding. [2]
4. In Resend **API Keys**, create a dedicated sending-access key for this website, restricted to the verified domain where available. Keep it private. A key value cannot be viewed later in the dashboard; save it securely or create a replacement if necessary. [3]
5. Have Manus open the protected website-settings card and supply these three values there: `RESEND_API_KEY` (the real sending key), `EMAIL_FROM` (the approved sender), and `APP_PUBLIC_URL` (`https://youcai-usq7zhae.manus.space`). Select Production availability for the live website, or all environments if you also want Preview to use it. Never paste the key into chat or a CRM customer/user field.
6. After values are saved, load the updated server environment and republish the website with explicit approval. A saved key alone does not prove a running deployment has loaded it. Verify a real test message and inbox receipt before treating registration/recovery as operational.

No paid plan, domain purchase or DNS change is made automatically. Your corporate recipient mailboxes stay at Alibaba Mail; the sender service is independent. The website provider should leave the existing root-domain receiving MX records and Alibaba Mail service unchanged and add only the required records for the approved sending subdomain. Do not enable a separate receiving/inbound service for this purpose.

## Message to forward to your website provider

> Please help enable transactional email for our Youcai CRM at https://youcai-usq7zhae.manus.space using Resend. We need a verified **sending-only subdomain**, for example notifications.youcaimedical.com, and a sender such as noreply@notifications.youcaimedical.com. Please use the exact sending DNS records generated by our Resend account. Leave all existing Alibaba Mail receiving services and root-domain MX records unchanged; do not configure Resend inbound receiving. Please confirm the domain shows Verified in Resend and provide the approved sender address. Keep the API key private—it will be entered directly into the website’s protected settings, not sent through a group message. If you need a different subdomain to avoid conflicts, please propose it before making changes.

## What becomes available

Ordinary applicants can register, receive a verification email and confirm their personal password through the website. They still remain pending until an administrator approves them. The five owner-provisioned initial administrators retain direct login; enabling mail must not change their role/status or falsely mark their email as verified.

Email-based recovery for a completed owner-provisioned administrator additionally requires the targeted recovery compatibility update in the application. It is implemented and passes 32 isolated router tests, typechecking and production build, but is not yet published. Deploy it together with genuine mail settings after explicit approval. Pending setup invitations or unverified ordinary users must not receive privileged recovery merely from an email-string match. Password reset changes only the credential and revokes sessions; it does not restore removed roles or reactivate suspended accounts.

This guide is not confirmation that a sender is verified, a provider key works, or any message has reached an inbox. The actual live delivery readiness is checked separately.
